# Теневое сравнение моделей

Инструмент сравнивает четыре уровня поверх уже запечатанных результатов
научного портфеля и сочетаний C1–C4:

1. предварительно зарегистрированное научное правило;
2. сглаженную вероятностную оценку;
3. регуляризованную логистическую модель;
4. неглубокую модель усиления деревьев.

Он не меняет формулы гипотез, причинный шлюз доказательств или продуктовые
заявления.

Сначала существующие неизменяемые артефакты преобразуются в локальный набор
данных без повторного скачивания рынка:

```bash
python scripts/research_build_scientific_shadow_dataset.py \
  --prospective-artifact-root var/research/prospective-partitions \
  --combination-artifact-dir var/research/scientific-combinations/<run> \
  --output-dir var/research/model-shadow/input
```

Затем выполняется сравнение:

```bash
python scripts/research_compare_scientific_shadow_models.py \
  --input-dir var/research/model-shadow/input \
  --output-dir var/research/model-shadow/runs
```

Разбиение всегда хронологическое по торговым дням: 60% для обучения, 20% для
настройки калибровки и 20% для окончательной проверки. Случайное смешивание
строк не используется. В результате сохраняются:

- точность и квадратичная ошибка вероятности;
- калибровка вероятностей;
- охват и доля воздержаний;
- доля полезных случаев среди выбранных;
- средний результат после издержек и версия модели издержек;
- явное состояние `blocked_by_data`, если данных, дней, классов или доступной
  библиотеки недостаточно.

Порог действия выбирается только на последовательной проверочной части. На
окончательной части он уже не меняется. Для каждого исследования создаётся
`selection.csv`: там либо выбран простейший устойчивый вариант, либо записано
решение воздержаться. Более сложная модель допускается только когда на
проверочной и окончательной частях одновременно:

- доля полезных случаев выше минимум на заданную величину;
- средний результат после издержек не хуже;
- ошибка вероятности не выше;
- охват не ниже установленного минимума.
- положительный результат сохраняется минимум в четырёх из пяти
  последовательных блоков окончательной части.

По умолчанию минимальный охват равен 10%, а требуемое улучшение доли полезных
случаев — двум процентным пунктам. Эти значения фиксируются в отпечатке
политики запуска.

Каждый запуск неизменяем и защищён контрольными суммами. В манифесте всегда
фиксируются `causal_evidence_gate_unchanged=true` и `claim_allowed=false`.
