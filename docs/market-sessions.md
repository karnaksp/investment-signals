# Уведомления об открытии торгов

Короткие уведомления идут в существующий Telegram-чат и тему в минуту
открытия сессии. Показываются рынок, классы инструментов, местное время
и время Стамбула. Часовой пояс отображения меняется в
`conf/market-sessions.json` (`display_timezone`).

Это уведомления по биржевому расписанию. Они не проверяют фактическую первую
сделку и не определяют внеплановую остановку торгов. Для Forex явно подписано
условное начало активности финансового центра: единого открытия OTC-рынка нет.

## Покрытие

| Рынок | Открытие по местному времени |
| --- | --- |
| Австралия, ASX | 10:00, основная сессия |
| Япония, Tokyo/JPX | 09:00 |
| Китай, Shanghai/Shenzhen | 09:30, непрерывные торги акциями |
| Гонконг, HKEX | 09:30 |
| Китай, SHFE | 09:00 дневная; 21:00 ночная для допущенных товаров |
| Россия, MOEX | 09:00 основная сессия; 09:50 в разрешённые выходные/праздники |
| Великобритания, LSE | 08:00 |
| Германия, Xetra | 09:00, основная сессия |
| США, NYSE/Nasdaq | 09:30, основная сессия |
| США, CME Globex/COMEX/NYMEX | 17:00 Чикаго: GC, SI, HG, CL, NG |
| Валютные центры | Сидней 08:00, Токио 09:00, Лондон 08:00, Нью-Йорк 08:00 |

Всего 15 расписаний. Каждое открытие имеет отдельное уведомление, включая
одновременно открывающиеся рынки. Возобновление после обеденных перерывов,
закрытия, премаркет и дополнительные утренние/вечерние сессии Мосбиржи
в текущую подписку не входят. Ночная сессия SHFE включена отдельно.

Валютные центры учитывают рабочие даты соответствующего местного фондового
календаря. Это выбранная конвенция уведомлений, а не утверждение об отсутствии
FX-сделок в местные биржевые праздники. Сидней по понедельникам сдвигается
до общего недельного открытия Forex, если 08:00 ещё попадает в выходные.

## Календари и ограничения

Адаптер использует `pandas-market-calendars==5.6.0`; pandas и внешние календари
остаются в адаптерах. Домен и application получают только `SessionOpening`.
`zoneinfo` пересчитывает DST независимо для каждой площадки; разные недели
перехода США и Европы не заменяются фиксированными UTC-смещениями.

Для Мосбиржи используется официальный календарь 2026 года, а не устаревший
XMOS из библиотеки: с 14 сентября основная сессия начинается в 09:00;
4 ноября открытие дополнительной сессии в 09:50; 28–29 ноября биржа закрыта.
Выходные и праздничные сессии включаются только согласно этому календарю.

Календарь Китая и MOEX подтверждён до **31 декабря 2026**. До нового года
нужно обновить даты и `valid_through` по официальным публикациям. За пределами
подтверждённого периода эти рынки не отправляют уведомления, worker помечает
здоровье как degraded; остальные рынки продолжают работать. Исключения и
чрезвычайные закрытия требуют обновления календаря и перезапуска worker.

Для CME используется календарь энергии и металлов, не календарь NYSE и не
календарь зерновых/крипто. Воскресное открытие фактически датировано воскресеньем,
хотя торговый день CME уже понедельник. Ночь SHFE привязана к фактической пятнице
для понедельничной торговой даты; перед праздничным закрытием ночного алерта нет.

## Запуск и доставка

```bash
# Проверка ближайших 24 часов, без БД и отправки:
python -m tinvest_signal_engine.services.session_open_worker --preview

# Установка только календарного worker, без пересборки всего стека:
docker compose build session-open-worker
docker compose up -d --no-deps --no-build session-open-worker
```

Нужны работающие Postgres с актуальными миграциями и `delivery-worker`.
Продюсер читает только пароль Postgres и идентификатор Telegram-направления;
бот-токен остаётся у delivery-worker. При обновлении кода доставки требуется
пересоздать delivery-worker с текущим `src`.

Каждые 5 секунд worker выбирает открытия текущей минуты. Детерминированные ID
по рынку и UTC-времени сохраняются с сигналом и outbox в одной транзакции.
Перезапуск и второй экземпляр продюсера не создают второе задание доставки.
Это не обещание exactly-once Telegram: потеря ответа после принятия сообщения
сервером остаётся неоднозначной сетевой ошибкой существующего транспорта.

И первоначальная отправка, и повтор после сетевой ошибки проверяются на
`opens_at <= now < opens_at + 60 секунд`. После минуты уведомление становится
`session_open_outside_minute`; пропущенные открытия не рассылаются при старте.
Обычная задержка — цикл 5 секунд, очередь доставки и сеть Telegram. Непрерывная
доступность сервера и Telegram необходима для получения в нужную минуту.

Health snapshot: `var/runtime-health/session-open-worker.json`.
Docker healthcheck проверяет свежесть файла и состояние `active`.
