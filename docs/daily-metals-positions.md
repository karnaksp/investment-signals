# Сырьё: позиции игроков

Отчёт приходит как **отдельная картинка и короткая подпись по каждому активу**.
Все источники по золоту находятся на карточке золота; все источники по серебру —
на карточке серебра. Большой текст с девятью рынками больше не отправляется.

## Как читать карточку

Внутри каждого источника видны группы участников, две подписанные полосы
лонгов и шортов, а под ними — одно предложение об изменении перевеса.
Зелёный соответствует лонгам, красный — шортам. Полосы всегда имеют общую
нулевую базу и показывают **доли внутри конкретной группы**:
`longs / (longs + shorts)` и `shorts / (longs + shorts)`.

Это доли направленных позиций без spreading, не доли всех участников рынка,
не отношение к открытому интересу, не денежный оборот и не прогноз цены.
Проценты в подписях округлены до целых; длины полос рассчитываются из исходных
количеств. Группа без направленных позиций показывается нейтральной полосой.
Числа изменений — контракты. Биржи и инструменты не суммируются.

«Перевес лонгов сократился» означает уменьшение `лонги − шорты`, пока эта
разность положительна; это не обязательно продажи или переход в шорт.
Смена стороны и исчезновение перевеса имеют собственные подписи.
В начале текстовой подписи — вывод по основной группе каждого источника.
Без изображения остаются доступными вывод, даты и ссылки на первичные данные.

## Источники внутри активов

| Активы | Источник | Период и группы на изображении |
| --- | --- | --- |
| Золото AU, серебро AG | SHFE | День: «Через брокеров», «Напрямую на бирже» |
| Золото и серебро COMEX, платина и палладий NYMEX, медь COMEX, WTI и Henry Hub NYMEX, пшеница SRW CBOT | CFTC, disaggregated futures only | Неделя: фонды и производители/торговцы/потребители |
| Brent ICE Futures Europe | ICE, futures only | Неделя: те же две группы |

Золото и серебро имеют по два блока: дневной SHFE и недельный CFTC.
Остальные семь карточек содержат по одному недельному источнику.
Даты сравнения находятся непосредственно над группами; недельные данные
явно обозначены как данные с задержкой. Даже в одной карточке разные даты
не выдаются за единое наблюдение.

Группы SHFE обозначают способ доступа, а не физические и юридические лица.
Через брокеров торгуют также организации; это не собственные ставки брокеров.
Фонды — категория managed money. Производители/торговцы включают потребителей,
и их шорт может быть хеджем.

Все пять категорий CFTC/ICE, включая swap dealers, other reportables,
nonreportable и spreading, точные количества и ОИ сохраняются в payload.
Картинка показывает только две основные группы. Исходные ответы и SHA-256
позволяют восстановить расчёт независимо от округления в изображении.

## Проверка первичных данных

- [SHFE: таблицы биржи](https://www.shfe.com.cn/reports/tradedata/dailyandweeklydata/?query_params=pm):
  `https://www.shfe.com.cn/data/tradedata/future/dailydata/pmYYYYMMDD.dat`.
- [CFTC: официальный API](https://publicreporting.cftc.gov/resource/72hh-3qpy.json),
  [описание API](https://publicreporting.cftc.gov/stories/s/COT-Help/p2fg-u73y/).
- [ICE: годовые CSV](https://www.ice.com/cot-report-links):
  `https://www.ice.com/publicdocs/futures/COTHistYYYY.csv`.

SHFE использует полные строки `auall`/`agall`, а не сумму топ-20 или рейтингов
по отдельным срокам. Проверяются успешный статус, дата, обе полные категории,
целые неотрицательные количества, отсутствие дублей и баланс лонгов/шортов.
Разность снимков должна совпасть с опубликованными изменениями.
Поиск двух сессий ограничен 15 календарными днями. Пропуск файла за праздник
допустим; сетевой сбой не считается праздником. Основной SHFE старше семи дней
или его ошибка останавливают текущий сбор.

CFTC и ICE: только `FutOnly`, без смешения с options, micro или альтернативными
рынками на тот же товар. Для обоих снимков суммы пяти групп, включая spreading,
сходятся с ОИ по обеим сторонам. CFTC дополнительно сверяет опубликованные
изменения групп и ОИ с предыдущим снимком. Пустые поля изменений ICE не
заменяются нулями: разности рассчитываются по двум реальным строкам.
Максимальный возраст недельной даты — 14 дней, разрыв между датами — 1–10 дней.
В январе при необходимости используется также прошлогодний CSV ICE.

Исходные ответы атомарно сохраняются после проверки в
`var/shfe-daily-positions/raw` и `var/shfe-daily-positions/context`.
Недельный кеш фиксирует первый проверенный ответ за UTC-день. Январский архив
ICE может содержать оба годовых CSV с сохранёнными заголовками. Недоступный
дополнительный источник явно отмечается на соответствующей карточке;
его отсутствие не превращается в позиции 0 и не блокирует SHFE.

## Расписание и защита от повторов

Существующие job `shfe_daily_positions_job` и schedule `shfe_daily_positions`
сохранены: будни, **13:00 и 15:00 Europe/Moscow**. Второй запуск повторяет
попытку при поздней публикации.

Новая версия — `commodity_asset_v1`. У каждого актива собственные event,
сигнал и outbox-запись. Идентичность — версия, актив, основной источник и дата
его наблюдения. Для золота/серебра основной источник SHFE; для остальных —
CFTC или ICE. Поэтому новый день создаёт две новые карточки металлов,
а семь неизменившихся недельных отчётов не рассылаются повторно.

Смена времени скачивания и изменения других рынков внутри годового ICE CSV
или общего CFTC JSON не меняют идентичность недельного отчёта данного актива.
Его фактические группы, даты и ОИ остаются частью проверяемого события;
противоречащая ревизия этих данных при той же дате отклоняется.
Для SHFE также проверяется SHA основного файла. Дополнительный контекст
фиксируется в первой сохранённой карточке за основную дату.

Переход со старого общего отчёта создаёт один первоначальный комплект карточек
по доступным активам; это отдельная версия. Повторный сбор не создаёт дублей.
Старые версии `shfe_daily_v1` и `commodity_positions_v1` в очереди поддерживаются.

Карточки атомарно сохраняются с inbox и durable outbox, без checkpoint или
rolling state детектора. Telegram отправляется одним `sendPhoto` на карточку
с подписью до 1024 символов. Загрузка PNG сохраняет проверку TLS, системный DNS
и переход к другому адресу только до начала HTTP-обмена. Отправка после
неопределённого HTTP-исхода не дублируется немедленным текстовым fallback.

Возраст материализации ограничен шестью часами; источник — семью днями для
дневной карточки и 14 днями для недельной. Обычные realtime-сигналы сохраняют
свои строгие ограничения и прежнюю текстовую доставку.

## Предварительный просмотр и обновление

```bash
python -m tinvest_signal_engine.services.daily_positions --dry-run
```

Команда печатает короткие подписи и сохраняет PNG в
`var/shfe-daily-positions/cards/{commodity}.png`, без БД и отправки.
PNG строится программно из проверенных данных с Pillow и шрифтом DejaVu Sans
в Linux (`fonts-dejavu-core`), Arial используется для локального macOS-просмотра.
Нет сгенерированных моделью чисел или графических оценок вероятности.

Запуск с постановкой в очередь:

```bash
python -m tinvest_signal_engine.services.daily_positions
```

При первом включении графики добавляются Pillow и шрифты, поэтому нужны
образы только двух затронутых сервисов:

```bash
docker compose build dagster-daemon delivery-worker
docker compose up -d --no-deps --no-build --force-recreate dagster-daemon delivery-worker
```

Инфраструктура и остальные микросервисы не пересобираются. Последующие
изменения шаблона применяются через существующий `live-src` mount после
пересоздания этих сервисов.
