# Дневные позиции в золоте и серебре SHFE

Сводка сравнивает последнюю доступную торговую сессию SHFE с предыдущей
доступной сессией. Это фактические количества контрактов в Китае, не оценка
направления сделок по цене и не позиции участников Мосбиржи.

## Что приходит в Telegram

Один отчёт на торговую дату по золоту AU и серебру AG:

- лонги и шорты клиентов брокеров и неброкерских участников;
- изменение каждого количества к предыдущей сессии, в контрактах и процентах;
- отношение лонг/шорт и его предыдущее значение;
- чистая позиция `лонги − шорты` и её изменение;
- общее количество открытых контрактов и его изменение.

Клиентские позиции брокеров нельзя интерпретировать как собственную ставку
брокера. Неброкерские участники также не являются автоматически «умными деньгами».
Размеры контрактов разных металлов различаются: отчёт не складывает их объёмы
и не выдаёт рост денежной оценки из-за цены за дополнительный набор.

## Источник и проверки

Официальные файлы:
`https://www.shfe.com.cn/data/tradedata/future/dailydata/pmYYYYMMDD.dat`.
[Таблицы биржи](https://www.shfe.com.cn/reports/tradedata/dailyandweeklydata/?query_params=pm).

Используются полные строки `auall` и `agall` по двум категориям участников,
охватывающие все сроки вместе. Рейтинг топ-20 и суммы по его отдельным срокам
не суммируются: смена состава такого рейтинга не должна выглядеть как набор
позиций. Перенос позиции между сроками не меняет совокупную позицию категории,
если её общий размер сохранился.

Перед сравнением проверяются дата ответа, успешный статус, наличие обеих
категорий для обоих металлов, целые неотрицательные позиции, отсутствие дублей
и равенство суммарных лонгов и шортов на уровне каждого металла. Разность
двух снимков должна совпасть с изменением за день, опубликованным SHFE.
Сеть, HTML вместо JSON, неполный файл или противоречащие итоги останавливают
расчёт. Пропуски не заменяются нулями.

Исходные файлы атомарно сохраняются в `var/shfe-daily-positions/raw` вместе
с их исходным содержимым; SHA-256 обоих файлов сохраняется в записи отчёта.
Поиск двух последних сессий ограничен 15 календарными днями. Выходные
пропускаются, отсутствие файла за праздник допустимо. Сетевой сбой не считается
праздником. Отчёт старше семи календарных дней не отправляется.

## Запуск и доставка

`conf/shfe-daily-positions.json` включает сбор. Для предварительного просмотра
без записи в Postgres и отправки в Telegram:

```bash
python -m tinvest_signal_engine.services.daily_positions --dry-run
```

Для сбора и постановки в существующий durable outbox:

```bash
python -m tinvest_signal_engine.services.daily_positions
```

Dagster job `shfe_daily_positions_job` запускается по рабочим дням в **13:00
и 15:00 по Москве**. Второй запуск — повторная попытка при поздней публикации;
уникальная идентичность торговой даты предотвращает вторую отправку того же
отчёта. Новая временная метка скачивания не меняет его идентичность.

Отчёт сохраняется атомарно с inbox и Telegram outbox. Он не создаёт контрольную
точку детектора и не попадает в его rolling state. Для типа
`daily_futures_position_report` действует отдельная ограниченная свежесть:
постановка в очередь не старше шести часов и данные не старше семи дней.
Поэтому вчерашний дневной отчёт может быть доставлен сегодня с явными датами;
обычные realtime-сигналы сохраняют прежние строгие ограничения.

В отчёте нет искусственного quality score или вероятности прибыли.
Отправка подтверждается обычным delivery worker; повтор того же дня не создаёт
дополнительных задач доставки. Для первоначального включения достаточно
пересоздать `dagster-daemon` и `delivery-worker` без сборки остального стека.
