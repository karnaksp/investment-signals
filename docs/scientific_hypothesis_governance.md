# Научный шлюз гипотез

Системная гипотеза проходит цепочку «первичная публикация → экономический
механизм → проверяемая формула → воспроизведение на Московской бирже →
независимая проверка → применённый каталог либо отклонение».

Публикация является источником исследовательской идеи, но не доказательством
работоспособности на Московской бирже. Решение о допуске принимает сценарий
`AssessScientificHypothesisAdmission`, который не зависит от YAML, базы данных
или веб-интерфейса.

## Происхождение и маркировка

- `research_derived` — прямое воспроизведение научной работы;
- `research_extension` — развитие опубликованного механизма;
- `author_proposed` — авторская гипотеза;
- `data_discovered` — закономерность, найденная в данных.

Только первые два типа могут иметь признак `scientific_claim: true`. Авторская
или найденная в данных гипотеза может стать локально подтверждённой и попасть в
применённый каталог, но не получает маркировку научной поддержки.

## Неизменяемая предварительная регистрация

До независимой проверки запечатываются направление, признаки, пороги, фаза
рынка, горизонты, критерий успеха, условия отказа, модель издержек, разбиение
данных и поправка на множественные проверки. Их отпечаток вычисляется
детерминированно. Изменение любого параметра требует новой, большей
семантической версии гипотезы и новой независимой проверки.

Для допуска обязательны:

- ссылки на существующие источники и хотя бы одна первичная публикация;
- проверяемое утверждение и критерий опровержения;
- запечатанная предварительная регистрация той же версии;
- подтверждённая независимая проверка именно на MOEX;
- результат после издержек, контрольные события, поправка на множество
  проверок и проверка устойчивости;
- локальный неизменяемый артефакт результата.

Отрицательные и неопределённые результаты остаются в реестре, но не допускаются
в `applied_catalog`.

## Реестр и проверка

Версионированный пример источников находится в
`config/scientific_hypotheses/registry-v1.yaml`, а машинная схема — в
`config/scientific_hypotheses/registry-schema-v1.json`.

Проверка выполняется до сборки применённого каталога:

```bash
PYTHONPATH=src python scripts/validate_scientific_hypothesis_registry.py
```

Коды происхождения, доказательности и жизненного цикла являются стабильным
контрактом реестра:

- доказательность: `researching`, `promising`, `validated`, `strict_90`,
  `rejected`;
- жизненный цикл: `draft`, `evaluated`, `applied`, `rejected`.
